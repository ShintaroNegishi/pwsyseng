# 科目の地図 — 5 テーマをどうつなぐか

略語と正式名称は [用語・略語集](glossary.md) にまとめています。

この科目は、見かけ上ばらばらな 5 つのテーマを扱います。

- 潮流計算
- 経済負荷配分
- 発電機起動停止計画
- アデカシーとセキュリティ
- 発電機の過渡安定度・定態安定度（genstab）

しかしこれらは、**「需要と供給を、どの時間スケールでも釣り合わせ続けられるか」**
という 1 つの問いを、違う時間スケールで見ているだけです。

| 時間スケール | 問い | テーマ |
|---|---|---|
| ミリ秒〜秒 | 事故の瞬間に同期を保てるか | 過渡安定度 |
| 秒〜分 | 微小な擾乱で運転点が保てるか、周波数を戻せるか | 定態安定度・周波数制御 |
| 分〜時 | いま流れている潮流は制約を守っているか。1 回線失っても大丈夫か | 潮流計算・セキュリティ |
| 時〜日 | どの発電機をいくら動かすか。どれを起動しておくか | 経済負荷配分・起動停止計画 |
| 年 | そもそも設備は足りているか | アデカシー |

`gridops.plotting.timescale_map()` がこの表を 1 枚の図にします。
第 00 回で見せ、各回の冒頭で「いまどこにいるか」を確認してください。

> **この表を直したら `gridops.plotting.COURSE_THEMES` も直してください。**
> 時間スケールの区切り（秒）とテーマ名は表と定数の 2 か所に書かれています。
> 図と文書が食い違うと、学生はどちらを信じてよいか分かりません。

## 回どうしの受け渡し

教材が 1 本の線としてつながるように、前の回の出力が次の回の入力になるよう
組んであります。

- **01 → 02**: 第 01 回で「参照解の電圧から注入を計算すると発電と負荷に一致するか」
  を確かめます。第 02 回はその同じ式を **ゼロにする** 方程式として解きます。
  検算の式と解くべき方程式が同じものであることが、この 2 回の橋渡しです。
- **02 → 04**: 交流で解いた潮流と直流近似の差を測ります。枝 4-5 で交流の
  $|S|$ が直流の $P$ より 47.6% 大きいこと（0.5614 対 0.3803）が、
  「熱容量の判定を直流で行ってはいけない」根拠になります。
- **04 → 06, 09**: ここで作る PTDF / LODF が、直流最適潮流と N-1
  スクリーニングの土台です。
- **05 → 06**: ひとつの $\lambda$ が、系統制約が効いた瞬間に母線ごとに割れます。
- **07 → 02**: 起動停止計画で決めた出力を潮流計算に流し込みます。
  停止した発電機の母線が PV から PQ に変わることを
  `Case.effective_bus_types` が扱います。**この受け渡しを実際に通すのは
  第 19 回（`19_integrated`）の第 1 節**で、ピーク時刻に G3 が 2 台とも
  停止しているため母線 3 が PQ に落ち、第 01 回で数えた未知数が 14 から
  15 に増えます。第 07 回では入切表を作るところまでで、潮流には流しません。
- **09 → 17**: N-1 で拘束する枝の 1 つが 5-7 で、これは第 17 回の標準事故と
  **同じ枝**です。同じ 1 つの事象を、第 09 回では静的に（過負荷）、
  第 17 回では動的に（脱調）評価することになります。
- **02 → 17**: 第 17 回の多機系統は、これまで潮流解を外から与えていました。
  `gridops.interop.to_genstab(case, my_solution)` に置き換えると、
  **自分で解いた潮流解**で過渡安定度を計算できます。
  ここで前半と後半が 1 つの系統でつながります。
- **08 → 12**: 起動している同期機について、共通基準へ換算済みの慣性寄与の合計が、変動性電源の導入で
  減ることを第 08 回で定量化し、第 12 回の「慣性が減ると CCT が短くなる」に
  つなげます。
- **09 + 17 → 19**: 総合演習では、起動停止計画 → 経済負荷配分 → 潮流計算 →
  N-1 → SCED → 過渡安定度 → 年間 LOLE を通しで回します。
  締めくくりは $(P_{G2}, P_{G3})$ 平面に「経済最適点」「N-1 の実行可能領域」
  「CCT が保護動作時間を上回る領域」を重ねた 1 枚の図です。

## 穴埋めの 3 層

最適化のテーマでは「定式化は読めるが書けない」学生が必ず出ます。
`# TODO` の書式で 3 層に分けています。

```python
# TODO(L1): 式を 1 行埋めること（全員が到達すべき）
# TODO(L2): 関数・ループを書くこと（標準）
# TODO(L3): 設計判断。答えは一意でないので markdown で述べること
```

**L3 は `# BEGIN SOLUTION` / `# END SOLUTION` で囲まないでください。**
`tools/build_notebooks.py` は囲んだ範囲を丸ごと削って `...` に置換するので、
後続のセルが依存する変数の定義を囲むと穴埋め版が壊れます。
同じ理由で、`set_xlabel` / `legend` / `plt.show` などループ不変な後処理は
必ず SOLUTION ブロックの外に出してください。L3 の模範解答は markdown セルに置きます。
