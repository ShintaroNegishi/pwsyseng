# 最適化ソルバについて

## なぜ PuLP + CBC なのか

学生の手元で**ライセンスの問題を起こさない**ことを最優先しました。
教材コードから `gurobipy` の import は完全に排除しています。

| 候補 | 判断 |
|---|---|
| **PuLP + CBC** | 採用。定式化が数式に近い形で書けて可読性が高く、conda-forge に Windows / macOS / Linux のビルド済みバイナリがあります |
| `scipy.optimize.milp` (HiGHS) | 追加依存がゼロで CBC より速い（実測で約 12 倍）のは利点ですが、制約行列を自分で組む必要があり、変数のフラット化と添字の管理が教材のノイズになります |
| Gurobi | 却下。アカデミックライセンスの導入が学生には関門です。加えて pip 版に付く制限ライセンスは 2000 変数 / 2000 制約なので、**小さいモデルは解けて大きいモデルだけ解けない**という最も切り分けの難しい事態を招きます |

実測（Python 3.11 / PuLP 2.8.0 / CBC 2.10）: WSCC 9 母線の 7 号機 × 24 時間の
起動停止計画（夏の平日、予備力 10%、区分線形 4 分割）が **0.490 秒**で
最適解に到達します。総費用 75,598,046 円（燃料 65,058,046 / 無負荷 8,940,000 /
起動 1,600,000、起動 2 回）。授業規模には十分な余裕があります。

区分線形の分割数を振ると、目的値が **上から**単調に収束することも確かめられます。

| 分割数 | 総費用 [円] |
|---|---|
| 1 | 75,683,783 |
| 4（既定）| 75,598,046 |
| 16 | 75,591,159 |

凸な費用関数の割線は元の曲線の上側に来るので、**区分線形近似は必ず過大評価側**
です。この単調性は第 07 回の演習でそのまま使えます。

## CBC が見つからないとき

```
RuntimeError: 使える CBC が見つからない。
```

原因はほぼ次のどちらかです。

1. **`conda activate pwsyseng` を忘れている。** CBC は環境の `bin/` に入るので、
   環境を有効にしないと PATH に載りません。
2. **`coin-or-cbc` が入っていない。** conda-forge の `pulp` パッケージは
   CBC のバイナリを **同梱していません**。`environment.yml` は
   `coin-or-cbc` を別行で並べていますが、手で `conda install pulp` だけを
   打つとこれが漏れます。

```bash
conda activate pwsyseng
conda install -c conda-forge coin-or-cbc
python -c "import shutil; print(shutil.which('cbc'))"
python -c "import pulp; print(pulp.listSolvers(onlyAvailable=True))"
```

`COIN_CMD` か `PULP_CBC_CMD` のどちらかが出れば動きます。
なお pip でインストールした PuLP は CBC のバイナリを wheel に同梱しているので、
`PULP_CBC_CMD` がそのまま使えます。`gridops.solvers` は**両方に対応**しています。

## 双対変数の符号

`gridops.solvers` の docstring にも書いてありますが、重要なので再掲します。

需給バランス制約を

```python
prob += pulp.lpSum(p[i] for i in units) == demand, "balance"
```

の向き（**右辺に需要を正の符号で置く**）で書くと、

```python
prob.constraints["balance"].pi
```

が $\partial(\text{総費用})/\partial(\text{需要})$、すなわち限界費用そのものになります。
逆向きに書くと符号が反転します。同じ最適解・同じ物理なのに符号だけが変わるので、
**絶対値で比べるテストではすり抜けます。テストは符号込みで書いてください。**

不等式制約（線路容量など）の双対は符号が決まった向きに出ます。
混雑価格として使うときは符号を反転して正で保持します。
反転を忘れると混雑レントが負になり「送電権の収入がマイナス」という
結論になるので、`gridops.dispatch` は `DCOPFResult.congestion_price` を
必ず正で持ちます。

## 混合整数計画の整数解に影価格を直接対応させない

`unit_commitment` は混合整数計画なので、整数最適解に線形計画と同じ意味の
双対変数を返しません。連続緩和には双対がありますが、それを元の整数問題の
限界費用としてそのまま解釈することはできません。時間別の条件付き限界費用が
必要なときは、得られた入切を固定して線形計画に落とし直します。
`gridops.commitment.marginal_prices` がこの 2 段階を実行します。

## 解の縮退

同一諸元の号機が並ぶと、同じ費用の別解が多数存在します。
ソルバの版やスレッド数で入切表が変わりうるので、
**答え合わせは入切表ではなく総費用で行ってください。**

同梱ケースは同一発電所内の号機で燃料費をわずかにずらして縮退を減らしています。
対称性除去制約（同一諸元の号機は番号順に起動する）も用意していますが、
費用が少しでも違う号機に適用すると最適解を切り落とすので、
**完全に同一の号機にだけ**適用されます。

## 精度と打ち切り

`unit_commitment` の既定は相対ギャップ `1e-4`、打ち切り時間 60 秒です。
打ち切られた場合は「最適解ではなくギャップ付きの解を見ている」ことになるので、
`CommitmentResult.status` を必ず確認してください。
